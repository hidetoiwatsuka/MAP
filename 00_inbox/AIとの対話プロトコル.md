# AIとの対話プロトコル

> MAP（knowledge-map.md）を索引として使いながら、 任意のテーマについて「創造的に考え、AIと正しく会話する」ためのフレームワーク。

---

## 0. 前提：なぜプロトコルが必要か

AIは「聞かれたことに答える」機械であって、「何を聞くべきか」は教えてくれない。 問いの質が回答の質を決める。 このプロトコルは、あらゆる状況で「良い問いを立てる」ための思考手順。

---

## 1. 座標の特定 — 今どこにいるか

何かを考え始めたら、最初にやることは「この問題は地図のどこにあるか」を特定すること。

### 手順

**Step 1：領域の特定** 「この問題に関係する領域はどれか」を地図から拾う。 最低2つ、できれば3つ。1つしか出てこないなら、視野が狭い可能性がある。

```
例：心房細動のカテーテルアブレーション研究
→ 医学（循環器）× 情報科学（データ分析）× 統計学 × 生体医工学 × 倫理学
```

```
例：body-simで薬理モデルを実装する
→ 薬理学 × プログラミング言語 × 数学（微分方程式）× 生理学
```

```
例：曲を作る
→ 音楽 × 心理学（感情）× 物理学（音響）× 技術（DAW・録音工学）
```

**Step 2：相の特定** 自分が今、4つの相のどこにいるかを確認する。

|相|問いの形|例|
|---|---|---|
|記述|「これは何？」「どう分類される？」|「HPSDアブレーションとは何か」|
|機構|「なぜそうなる？」「どう動く？」|「なぜHPSDの方が組織損傷パターンが違うのか」|
|判断|「どうすべき？」「何を選ぶ？」|「この患者にはHPSDとSPSDのどちらが適切か」|
|表現|「どう伝える？」「どう実装する？」|「この結果を論文でどう示すか」「Rustでどう書くか」|

**Step 3：軸の確認** 3つの軸上で自分の位置を意識する。

- **スケール**：今見ているのはどの大きさか（分子？個体？集団？）
- **時間**：どの時間幅か（ミリ秒の現象？年単位の変化？）
- **確実性**：どの程度の確かさが期待できるか（数学的証明？統計的傾向？解釈？）

## 2. 深度の決定 — どこまで掘るか

座標がわかったら、各領域をどの深さまで理解すべきかを決める。

### 深度レベル

|レベル|名前|基準|AIとの対話で何ができるか|
|---|---|---|---|
|0|未知|存在すら知らない|何も聞けない|
|1|認知|「そういう分野がある」と知っている|「Xについて教えて」と聞ける|
|2|語彙|主要な概念と用語を知っている|「XのYについて教えて」と特定できる|
|3|構造|概念間の関係を理解している|「XとYの関係はどうなっている？」と聞ける|
|4|機構|なぜそうなるかを説明できる|「この説明は正しいか？」と検証できる|
|5|境界|どこで破綻するかを知っている|「この条件でもそれは成り立つか？」と突っ込める|

### 必要深度の判断基準

**本業の領域**（医学、プログラミング）→ レベル4〜5を目指す **本業に隣接する領域**（統計学、倫理学、生体医工学）→ レベル3〜4 **本業を支える基盤**（数学、物理、化学）→ レベル2〜3 **一般教養**（政治、経済、法律、歴史）→ レベル2 **遠い領域**（農学、服飾、スポーツ科学）→ レベル1

ただしこれは固定ではない。問題に遭遇したとき、必要に応じてその領域の深度を一時的に上げる。 AIがあれば、レベル1→3への一時的ジャンプは短時間でできる。 レベル4→5は時間と経験が必要。

## 3. 問いの設計 — 何をどう聞くか

座標と深度が決まったら、問いを設計する。

### 問いの型（テンプレート）

#### A. 探索型 — 何があるか知りたい

```
「[領域]の主要な概念を教えて」
「[テーマ]に関係する分野は何がある？」
「[X]の全体像を教えて」
```

深度レベル0→1、1→2への移行に使う。 注意：この問いだけで止まると「ふーん」で終わる。次の型に進む。

#### B. 機構型 — なぜそうなるか知りたい

```
「[X]はなぜ[Y]を引き起こすのか」
「[X]が起きるメカニズムを一段下のレイヤーから説明して」
「[X]の因果連鎖を教えて」
```

深度レベル2→3、3→4への移行に使う。 AIが最も力を発揮する問いの型。

#### C. 境界型 — どこで破綻するか知りたい

```
「[X]の説明が成り立たなくなる条件は？」
「[この原則]の例外は何がある？」
「[X]と[Y]が矛盾する場合はどうなる？」
```

深度レベル4→5への移行に使う。 この問いを立てられること自体が高い理解の証拠。

#### D. 接続型 — 他の知識とどう繋がるか知りたい

```
「[X]は[別の領域]から見るとどう説明できる？」
「[X]と[Y]の類推は成り立つ？どこで破綻する？」
「[X]の問題を[別の分野の手法]で解けないか？」
```

創造性の源泉。異なる領域の知識を接続するための問い。 地図上の離れたノード同士を結びつけることを意識する。

#### E. 判断型 — どうすべきか考えたい

```
「[状況]において、[選択肢A]と[選択肢B]のトレードオフは？」
「[X]を判断するとき、見落としやすい観点は？」
「この判断に関係するステークホルダーは誰か？」
```

判断の相での問い。AIに答えを求めるのではなく、判断材料を引き出す。 最終判断は人間がする。

#### F. 表現型 — どう伝えるか考えたい

```
「[X]を[対象読者]にわかるように説明するには？」
「[X]を[別の形式：コード/数式/図/物語]で表現して」
「この説明のどこがわかりにくいか指摘して」
```

表現の相での問い。AIとの対話そのものがこの型の実践。

#### G. メタ型 — 問い自体を問いたい

```
「この問題に対して、自分が見落としている問いは何？」
「今の自分の理解で、最も弱い部分はどこ？」
「この問題をもっと良く定義するにはどう聞くべき？」
```

最も強力な型。AIにメタ認知を補助してもらう。 ただしAIの回答も完璧ではないので、複数回聞いて角度を変える。

## 4. 検証 — AIの回答をどう評価するか

AIの出力を無批判に受け入れてはいけない。

### 検証チェックリスト

**事実の検証**

- この主張の根拠は何か（AIに聞く：「その情報のソースは？」）
- 確実性の軸上でどこに位置するか（証明済み？統計的傾向？一つの解釈？）
- 自分の既存知識と矛盾していないか

**構造の検証**

- 因果の方向は正しいか（相関を因果と言っていないか）
- スケールの混同はないか（個人の事例を集団に一般化していないか）
- 時間軸の混同はないか（短期的に正しいことが長期的にも正しいとは限らない）

**省略の検証**

- 重要な例外が省略されていないか
- 対立する見解が提示されているか
- 「判断の相」の問いに対して、トレードオフが明示されているか

**バイアスの検証**

- AIは学習データの偏りを持っている
- 英語圏・西洋中心のバイアスはないか
- 「一般的に」「通常は」の裏に隠れている前提はないか

### 検証が特に重要な場面

- 臨床判断に関わる情報
- 法律・制度に関する情報（国・地域で異なる）
- 最新の研究結果（AIの学習データは過去のもの）
- 文化的な価値判断を含む回答

## 5. 創造のプロトコル — 知識を組み合わせる

AIとの対話で最も価値が高いのは、既存の知識を新しく組み合わせること。

### 創造的接続の手順

**Step 1：テーマを地図上に置く** 今取り組んでいることの座標を特定する（セクション1）。

**Step 2：意図的に遠いノードを引き込む** 地図上で、今の問題から距離のある領域を1つ選び、そこからの視点を借りる。

```
例：アブレーション研究 ← 音楽の視点を借りる
「心臓の電気活動のリズムパターンは、音楽のリズム構造とどう類似している？
 リエントリーは不協和音のようなものか？」
```

```
例：Rustのエラーハンドリング ← 医学の視点を借りる
「Result<T, E> は鑑別診断のようなもの？
 Ok(T) = 正常所見、Err(E) = 異常所見で、
 パターンマッチは鑑別プロセスに対応するか？」
```

**Step 3：類推の妥当性を検証する** 借りてきた類推がどこまで有効で、どこで破綻するかをAIと一緒に検証する。

```
「この類推はどこで破綻する？」
「この類推から得られる実践的な洞察は何？」
```

**Step 4：破綻点から新しい問いを生む** 類推が破綻する地点に、最も面白い発見がある。 破綻の理由を掘ると、両方の領域に対する理解が深まる。

### 創造性を高めるAIへの問いかけ

```
「[X]を全く違う分野の人に説明するなら、どんなメタファーを使う？」
「[X]の問題を[Y]の専門家が見たら、何を指摘する？」
「[X]と[Y]には共通の数学的構造がある？」
「歴史上、[X]に似た問題が別の文脈で解かれたことはある？」
「[X]の逆を考えるとどうなる？（反転思考）」
```

## 6. 責任のプロトコル — 人間が担うもの

AIに委ねてはいけない判断がある。

### 人間が保持すべき判断

**倫理的判断**

- 「技術的にできるが、すべきか」
- AIに材料を集めさせ、判断は自分でする
- 特に医療：患者の利益、自律尊重、無危害、公正の4原則

**責任の所在**

- AIの出力に基づいて行動した結果の責任は人間にある
- 「AIがそう言ったから」は理由にならない
- 特に臨床判断、研究データの解釈、公的な発信

**文脈の判断**

- AIは目の前の患者の表情を見ていない
- AIはチームの人間関係を知らない
- AIは「今この瞬間」の空気を読めない
- 文脈に依存する判断は人間の領域

**価値の選択**

- 何を重要だと思うか、何に時間を使うか
- AIは選択肢を提示できるが、優先順位は自分でつける
- 人生の方向性を決めるのは人間

### AIに委ねてよいもの

- 情報の検索と整理
- 既知のパターンの適用
- 文章・コードの下書き
- 定型的な分析と計算
- 知識の相互接続の提案
- 自分の思考の壁打ち相手

## 7. 実践ワークフロー — 毎日の使い方

### 新しいテーマに出会ったとき

```
1. 座標を特定する（どの領域の交差点か？）
2. 深度を決める（今の目的にはレベル何が必要か？）
3. 探索型の問いで全体像を掴む
4. 機構型の問いで一段下に降りる
5. 接続型の問いで既知の領域と繋ぐ
6. 境界型の問いで限界を確認する
```

### 問題にぶつかったとき

```
1. 問題を言語化する（表現の相）
2. 問題の座標を特定する（領域 × 相 × 軸）
3. スケールか時間軸を変えてみる（違う角度から見る）
4. 隣の領域からの類推を試みる（接続型の問い）
5. AIに「自分が見落としている観点は？」と聞く（メタ型の問い）
```

### 何かを作りたいとき

```
1. 作りたいものの座標を特定する
2. 必要な領域の知識の深度を確認する
3. 足りない深度があれば、AIで一時的に引き上げる
4. 遠い領域からの接続を意識的に試みる（創造のプロトコル）
5. 作りながらAIと壁打ちする（表現型の問い）
6. 完成したら境界型の問いで検証する
```

## 8. プロトコルの進化

このプロトコル自体が固定されたものではない。

- 使ってみて機能しない部分は修正する
- 新しい問いの型を発見したら追加する
- 自分の深度レベルが上がったら、各領域の必要深度を見直す
- AIの能力が変わったら、人間とAIの分担線を引き直す

最終的に、このプロトコルが意識せずに回るようになったとき、 それは「AIと正しく会話する力」が身についたということ。

> 地図は索引、プロトコルは使い方、創造は自分の仕事。
